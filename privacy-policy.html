Política de Privacidad de Hiraeth

Responsable del tratamiento: Hiraeth — proyecto desarrollado por Necel. Contacto: neceldev@gmail.com. Jurisdicción: República Argentina (Ley 25.326 de Protección de los Derechos de los Usuarios de Bancos de Datos).

Hiraeth es un bot de Discord gratuito. Esta política explica qué datos maneja el bot, qué datos guarda, con qué terceros se comparten, durante cuánto tiempo y qué derechos tienes bajo la ley argentina. No usamos cookies, ni analítica web, ni publicidad, ni vendemos datos.

1. Datos de identidad

El bot solo maneja identificadores de Discord: las "snowflakes" (identificadores numéricos) de usuario, servidor, canal y mensaje, junto con nombres de usuario y URL de avatares que muestra Discord. Nunca solicita ni almacena correo electrónico, teléfono, dirección IP, domicilio físico o nombre real.

Los identificadores de usuario de Discord son pseudónimos. Si un usuario escribe a neceldev@gmail.com (por ejemplo, para solicitar una supresión), su correo y el contenido de ese mensaje se guardan en el buzón del operador únicamente para gestionar la solicitud.

2. Acceso al contenido de los mensajes

El bot tiene habilitado el privilegio de Message Content de Discord. Procesa temporalmente los mensajes en los servidores donde está presente con los siguientes fines: conteo de XP, escaneo de automoderación (palabras prohibidas, invitaciones, flood) y análisis del contador comunitario. La función opcional de chatbot con prefijo ! está activa y tiene un alcance acotado: procesa solo los mensajes que comienzan con ! y únicamente en el canal de chatbot que un administrador del servidor haya configurado. El resto de los mensajes del servidor no se envía a ningún proveedor externo ni se almacena.

Solo persiste lo que indica la tabla de la sección 3. No registra ni almacena el chat general. Además, los eventos de mensajes se observan para contar la actividad por servidor y por día: de cada mensaje solo se leen el servidor, el autor y la marca de tiempo, nunca el texto ni los adjuntos.

Hay una excepción acotada y explícita: cuando se cierra un ticket de soporte, el bot lee los mensajes de ese canal privado para generar la transcripción que entrega al servidor (ver sección 3). Esa lectura ocurre una sola vez, en el momento del cierre, y la transcripción no se guarda en la base de datos del bot.

Base de conocimiento del servidor (Q&A de admin, máx. 50 entradas/servidor) Preguntas y respuestas almacenadas indefinidamente hasta eliminarse con /knowledge remove. Mensajes anónimos (/anonimo) El mensaje se publica sin autor visible en el canal, pero el tag y el ID del autor se registran en un canal de registro del servidor visible para los moderadores. Mientras el canal de registro lo retenga (hasta que el servidor lo elimine).
Tickets de soporte (/ticket) ID de servidor, ID del canal privado, ID del usuario que abrió el ticket, tipo, prioridad, estado, asunto en texto libre escrito por el usuario (máx. 100 caracteres), ID del miembro del personal que lo reclamó, IDs de los participantes añadidos y marcas de tiempo de creación, última actividad, aviso de inactividad, cierre y entrega de la transcripción; además, el ID de quien lo cerró y el motivo de cierre. No se almacena el contenido de los mensajes del ticket ni la descripción libre que el usuario escribe al abrirlo: ambos existen solo en el canal de Discord. El canal privado se elimina automáticamente tras el cierre: la limpieza corre cada hora y respeta una ventana de 10 minutos en la que el ticket todavía puede reabrirse. El documento se purga automáticamente 30 días después del cierre mediante un índice TTL. Los tickets de un servidor también se eliminan cuando el bot es retirado de ese servidor. /data delete borra los tickets cerrados cuyo canal ya no existe y anonimiza el ID del usuario en los que siguen vinculados a un canal.
Sugerencias (/suggest) IDs de servidor, de canal y de mensaje de la tarjeta, el número de la sugerencia, el ID del autor, el contenido en texto libre escrito por el miembro (máx. 1000 caracteres), el estado (abierta/aprobada/rechazada/implementada), el ID de quien la decidió, un motivo de decisión opcional en texto libre (máx. 300 caracteres) y los contadores de votos a favor y en contra. Los votos se guardan aparte: ID de la sugerencia, ID del votante y dirección del voto, con una fila por usuario y sugerencia. Indefinida mientras el bot esté en ese servidor. Una sugerencia se elimina con /suggest delete (autor o personal). /data delete elimina los votos emitidos y las sugerencias escritas por el usuario, junto con las tarjetas que publicó el bot; las sugerencias y los votos de un servidor se eliminan cuando el bot es retirado de él.
Starboard (/starboard) IDs de servidor, de canal y de mensaje de origen, el ID de quien escribió el mensaje destacado, los IDs del canal y del mensaje del starboard y el recuento actual de estrellas. El texto del mensaje no se guarda en la base de datos: el destacado existe como mensaje de Discord en el canal que el servidor configuró. Se elimina automáticamente cuando el mensaje de origen se borra o cuando sus reacciones caen por debajo del umbral configurado. /data delete elimina los registros del usuario y las publicaciones que el bot hizo a partir de sus mensajes; los registros de un servidor se eliminan cuando el bot es retirado de él.
Canales de voz temporales (/tempvoice) ID del servidor, ID del canal temporal, ID del dueño, ID del canal hub, si el canal está bloqueado, el límite de usuarios, el ID del mensaje del panel de control del bot y, cuando una operación en segundo plano falla, un código de error con su marca de tiempo. No se guarda audio, contenido de mensajes ni datos de presencia. Se elimina cuando el canal queda vacío (tras 30 segundos de gracia), cuando el canal se borra o el dueño usa /tempvoice delete, y en la reconciliación de arranque entre la base de datos y Discord. /data delete elimina las filas donde el usuario es dueño y borra los canales que sigan existiendo. Las filas de un servidor se eliminan cuando el bot es retirado de él.
Canales de estadística (/statchannel) IDs de servidor y de canal, qué contador refleja el canal, la plantilla de nombre (escrita por administradores, máx. 100 caracteres), el último nombre renderizado, la marca de tiempo del último renombrado y, en caso de fallo, un código de error con su marca de tiempo. No se guardan datos de usuarios. Indefinida mientras esté configurada; se quita con /statchannel remove.
Notificaciones de ofertas y juegos gratis (/deals) ID del servidor, clave de la notificación, preset, ID del canal de anuncios elegido, si está activada y el ID de usuario del administrador que la creó, junto con sus ajustes: filtros (tiendas, descuento mínimo, precio original mínimo, nota mínima de Metacritic y de Steam, inclusión de juegos gratis para siempre), tema visual, imágenes, si abre un hilo, si anuncia ofertas próximas, si publica y reacciona de forma automática y el rol al que se menciona, con su ID. Un servidor puede tener hasta seis notificaciones. La función es opcional por servidor y la configura un administrador con /deals; el bot solo publica en el canal que el servidor eligió. No se guardan nombres de miembros ni contenido de mensajes. Indefinida: la notificación no tiene TTL y se conserva hasta que el servidor la elimina desde /deals o hasta que el bot es retirado del servidor. /data delete borra el ID de quien la creó y conserva la notificación, porque pertenece al servidor y no a la persona; /data export incluye las notificaciones que creó el usuario.
Registro de anuncios de ofertas ID del servidor, ID de la notificación, ID de la oferta, ID del canal, los IDs del mensaje publicado y del hilo creado cuando corresponde, el estado del envío y las marcas de tiempo del intento de envío y de la publicación. Es el registro que impide avisar dos veces de la misma oferta al mismo servidor. No contiene contenido de mensajes. Un índice TTL los purga automáticamente 90 días después de la publicación (postedAt); un registro que nunca llegó a publicarse no tiene esa marca y no vence solo, y todos los registros de un servidor se eliminan cuando el bot es retirado de él.
Catálogo de ofertas Título, descripción, tienda, precios (original, final y descuento), nota de Metacritic y de Steam, miniatura, URL de la oferta y fechas de la promoción, además de una traducción al español del título y la descripción cuando la fuente la ofrece. Son datos de las tiendas: ninguna fila del catálogo lleva ID de usuario ni de servidor. Un índice TTL los purga automáticamente 90 días después de la fecha de vencimiento de la promoción que registra la fila.
Anuncios programados (/announce) ID del servidor, su número en /announce list (1 a 10), ID del canal de destino, hasta 5 mensajes de texto libre escritos por administradores (máx. 1500 caracteres cada uno), el horario (diario, semanal o por intervalo, con la zona horaria del servidor), el modo de mención (ninguna, rol o @here) con el ID del rol cuando corresponde, si el anuncio está en pausa y el motivo cuando la pausa la aplicó el propio bot, la marca del último envío y el ID del administrador que lo creó. Un servidor puede tener hasta 10 anuncios. No se almacena contenido escrito por miembros ni el texto de los mensajes a los que el bot responde. Indefinida mientras el servidor lo conserve: se elimina con /announce remove o cuando el bot es retirado del servidor. /data delete borra el ID de quien lo creó y conserva el anuncio, porque pertenece al servidor y no a la persona; /data export incluye los anuncios que creó el usuario.
Roles temporales (/temprole) ID del servidor, ID del usuario, ID del rol, el instante de vencimiento y el ID del moderador que otorgó el rol. El trabajo programado que aplica el vencimiento guarda además el ID del usuario y del rol en su carga. No se almacena contenido de mensajes. El registro se elimina cuando el vencimiento se ejecuta (el rol se retira y el trabajo se descarta), cuando un moderador lo revoca con /temprole remove y cuando el bot es retirado del servidor. /data delete borra el registro y el trabajo programado asociado; si eso ocurre, el rol puede quedar asignado en el miembro, porque el bot ya no conserva el registro que lo marcaba como temporal, y es un moderador quien debe retirarlo.
Aniversarios de ingreso (/anniversary) La configuración por servidor (activación, ID del canal e ID del rol) forma parte de la configuración del servidor. Además, cada miembro que lo solicita deja una fila de exclusión con su ID de usuario y el ID del servidor, y el bot mantiene un marcador diario por servidor con la fecha local (YYYY-MM-DD) y el instante en que ese día quedó reservado. La fecha de ingreso no se almacena: se lee del miembro en Discord en el momento de anunciar, y el marcador no contiene datos de miembros. La fila de exclusión se conserva hasta que el miembro la revierte con /anniversary optin, hasta que pide la supresión con /data delete o hasta que el bot es retirado del servidor. El marcador diario se auto-elimina 7 días después de la reserva mediante un índice TTL y también se borra cuando el bot es retirado del servidor.
Trabajos programados (planificador interno) Identificador estable del trabajo, ID del servidor, tipo de función, el horario (con la zona horaria del servidor) y la carga propia de esa función —por ejemplo el ID de usuario y de rol de un rol temporal, o el número interno de un anuncio—, además del próximo instante de ejecución, las marcas de la última ejecución y de la reserva en curso, y contadores de ejecuciones y fallos. No contiene contenido de mensajes. Un trabajo de una sola ejecución se elimina en cuanto se completa; los recurrentes (anuncios, aniversarios y la carrera semanal de XP) persisten mientras la función siga programada y se eliminan cuando se desregistra, cuando el servidor desactiva la función o cuando el bot es retirado del servidor. /data delete borra los trabajos cuya carga referencia al usuario.

Tickets de soporte: un ticket es un canal privado visible para quien lo abre, para el personal con el rol de soporte configurado y para los administradores del servidor. Al cerrarlo, el bot genera una transcripción leyendo hasta 1000 mensajes de ese canal (2 MB como máximo) y la entrega como archivo de texto al canal de registro configurado por el servidor o, si no hay ninguno, al mensaje directo de quien abrió el ticket. Hiraeth no guarda esa transcripción en su base de datos: queda únicamente en el canal o el mensaje directo de Discord que la recibe, bajo el control de ese servidor.

4. Terceros

Flujos exactos de datos con terceros:

  • Google (Google LLC) — modelo Gemma gemma-4-26b-a4b-it, accedido a través de la Gemini API / Google AI Studio en la cuota no pagada (gratis): esta función no se ejecuta en la cuota de pago de Google. Recibe el texto del mensaje del chatbot (≤1500 caracteres), hasta las últimas 20 entradas de historial previo (10 pares de mensaje y respuesta), el texto de persona configurado por el admin del servidor y hasta 3 entradas de conocimiento Q&A del admin que coincidan. No recibe IDs de usuario de Discord, IDs de servidor, nombres de usuario ni avatares. El procesamiento puede ocurrir en servidores fuera de Argentina (transferencia internacional). 5. Resumen de retención

Los TTL automáticos figuran en la tabla anterior. La economía virtual, las estadísticas de juegos y las tareas personales están vinculadas a la cuenta de cada usuario a través de todos los servidores y persisten de forma indefinida hasta que se eliminan mediante los mecanismos listados o por solicitud de supresión. Los datos de ámbito de servidor, en cambio, se purgan automáticamente cuando el bot es retirado de ese servidor (ver más abajo).

Los datos no se borran automáticamente cuando un usuario sale de un servidor. Las solicitudes de supresión son el medio por el cual los usuarios cierran esa brecha. Lo señalamos con honestidad.

Cuando Hiraeth es retirado de un servidor, se purgan automáticamente los datos almacenados de ese servidor: las advertencias de moderación y las acciones moderadas programadas pendientes, las entradas de la base de conocimiento Q&A del servidor, las encuestas, los recordatorios pendientes, el registro agregado del contador comunitario y sus registros de fallo, los registros de XP, los agregados diarios de XP y los registros de temporada, los agregados diarios de actividad del servidor y los marcadores de miembro activo, las propuestas y votos de noches de película, los tickets de soporte de ese servidor, las sugerencias y sus votos, los registros de starboard, las filas de los canales de voz temporales, las notificaciones de ofertas y sus registros de anuncios, las conversaciones del chatbot de IA, los datos de cumpleaños, los anuncios programados, los roles temporales concedidos, las filas de exclusión y los marcadores diarios de aniversarios y los trabajos programados de ese servidor; las sesiones de juego activas de ese servidor se cierran automáticamente. La purga es por mejor esfuerzo y se ejecuta de forma independiente por categoría de datos, de modo que un fallo en una categoría no impide el borrado de las demás. Los datos vinculados a la cuenta de cada usuario a través de todos los servidores —la economía virtual, las estadísticas de juegos y las tareas personales— no dependen de un solo servidor y no se eliminan con esta purga; la configuración del servidor creada por administradores también se conserva por si el bot vuelve a ser invitado. Cualquier persona puede seguir eliminando o solicitando la supresión de todos sus datos en cualquier momento mediante /data o escribiendo a neceldev@gmail.com (objetivo de respuesta: dentro de los 30 días). Los dos TTL de analítica son de 400 días para los contadores diarios y de 35 días para los marcadores de miembro activo; el de los tickets de soporte es de 30 días desde el cierre, el marcador diario de aniversarios es de 7 días desde la reserva, y el catálogo de ofertas y el registro de anuncios se purgan a los 90 días —el primero desde que termina la promoción, el segundo desde la publicación—, mientras que las notificaciones de ofertas no vencen solas. El registro de activación de módulos opcionales se conserva mientras exista el servidor y se elimina con la purga de datos de ese servidor, sin un vencimiento propio. Cuando una persona pide la supresión de sus datos, el bot elimina además los mensajes de Discord que publicó en su nombre (sus tarjetas de sugerencia, sus destacados del starboard y sus canales de voz temporales), no solo las filas de la base de datos.

Hiraeth Privacy Policy

Data controller: Hiraeth — a project developed by Necel. Contact: neceldev@gmail.com. Jurisdiction: Argentine Republic (Law 25.326 on the Protection of the Rights of Database Users).

Hiraeth is a free Discord bot. This policy explains what data the bot handles, what data it stores, which third parties it shares data with, for how long, and what rights you have under Argentine law. We do not use cookies, web analytics, advertising, or sell data.

1. Identity data

The bot only handles Discord identifiers: user, guild, channel, and message ID snowflakes, along with usernames and avatar URLs shown by Discord. It never asks for or stores email, phone number, IP address, physical address, or real names.

Discord user IDs are pseudonymous. If a user writes to neceldev@gmail.com (for example, to request deletion), their email and the message content are stored in the operator's mailbox solely to handle the request.

2. Message content intent

The bot has Discord's Message Content privilege enabled. It temporarily processes messages in servers it is in for: XP counting, automod scanning (banned words, invites, flood), and community counter parsing. The optional !-prefixed chatbot feature is active and has a tightly bounded scope: it processes only messages beginning with !, and only in the chatbot channel an administrator has configured for the server. No other message in the server is sent to any external provider or stored.

It only persists what the table in section 3 lists. It does not log or store general chat. Message events are additionally observed to count activity per server per day: only the server, the author and the timestamp are read — never the text or attachments.

There is one narrow, explicit exception: when a support ticket is closed, the bot reads that private channel's messages to build the transcript it hands to the server (see section 3). That read happens once, at close time, and the transcript is not stored in the bot's database.

  • Google (Google LLC) — Gemma model gemma-4-26b-a4b-it, accessed through the Gemini API / Google AI Studio on the unpaid (free) quota: this feature does not run on Google's paid quota. It receives the chatbot message text (≤1500 chars), up to the last 20 previous history entries (10 message/response pairs), the server's admin-configured persona text, and up to 3 matching admin Q&A knowledge entries. It will not receive Discord user IDs, guild IDs, usernames, or avatars. Processing may occur on servers outside Argentina (international transfer). Google's handling of the data: because this is the unpaid quota, under the Gemini API Additional Terms of Service (in effect since 23 March 2026) Google may use the submitted content and the generated responses to provide, improve and develop its products, services and machine-learning technologies, and human reviewers may read, annotate and process the API input and output. That handling does not apply to the paid quota. Anyone using the chatbot with this model should know that their message and the model's reply may be used by Google in that way. The knowledge lookup is local (word-overlap scoring on the bot's own server) and is not sent to Google.
  • WeatherAPI: only the city name the user typed (weather lookup command).
  • YouTube Data API v3 (Google): only the search term typed by the user.
  • Open Trivia DB (opentdb.com): the /trivia command fetches its questions from opentdb.com. No user data is sent: the request only includes the selected category and difficulty. Questions are published under the CC BY-SA 4.0 license.
  • dolarapi.com: no user data at all (public rates).
  • Epic Games Store (Epic Games, Inc.) and CheapShark (cheapshark.com): the deal notifications query Epic's public promotions catalogue (store-site-backend-static.ak.epicgames.com) and the CheapShark API (www.cheapshark.com, an aggregator over several stores) every 15 minutes. These are unauthenticated catalogue reads: Hiraeth sends no member data, no guild ID and no identifier of any kind in those requests.
  • Mercado Pago (Mercado Libre S.R.L.): the payment provider behind the self-serve checkout for optional paid modules. When a server's administrator buys a plan, the payment page is hosted by the provider and it is the provider that receives the payer's name, e-mail, identification and payment instrument, together with the amount, under its own terms and privacy policy. What the bot receives is the outcome — whether the payment was approved, its amount and currency, and the provider's identifiers for the transaction — never the payment instrument or the payer's identity. No member data of the server is sent with that request.
  • Discord (Discord Inc.): the platform inherently hosting all IDs/content.
  • Database: MongoDB used by the bot; access restricted to the operator. No cookies, no web analytics, no advertising, no selling of data.

No API keys are ever exposed to users.

5. Retention summary

Automated TTLs are listed in the table above. The virtual economy, game statistics, and personal tasks are tied to each user's account across all servers and persist indefinitely until removed via the listed mechanisms or by a deletion request. Server-scoped data, in turn, is purged automatically when the bot is removed from a server (see below).

Data is not automatically erased when a user leaves a server. Deletion requests are how users close that gap. We state this honestly.

When Hiraeth is removed from a server, the data stored for that server is purged automatically: moderation warnings and pending scheduled moderation actions, the server's Q&A knowledge base entries, polls, pending reminders, the community-counter aggregate record and its failure records, XP records, daily XP aggregates and season records, server activity analytics aggregates and active-member markers, movie-night proposals and votes, the server's support tickets, its suggestions and their votes, its starboard records, its temporary voice channel rows, its deal notifications and their announcement records, AI chatbot conversations, birthday data, scheduled announcements, granted temporary roles, anniversary opt-out rows and daily markers, that server's scheduled jobs, the configuration its administrators wrote, its stat-channel configuration, its saved quotes and quote numbering, its suggestion numbering, and its roulette matches; active game sessions in that server are automatically ended, and any coins staked in its unfinished roulette matches are refunded before those matches are deleted. The purge is best-effort and runs independently per data category, so a failure in one category does not prevent the others from being deleted. Data tied to a user's account across all servers — the virtual economy, game statistics, and personal tasks — is not bound to a single server and is not removed by this purge. Because the server's configuration is deleted as well, a server that invites Hiraeth again starts from a clean configuration. Anyone can still delete or request erasure of all of their data at any time via /data or by emailing neceldev@gmail.com (target response time: within 30 days). The two analytics TTLs are 400 days for the daily counters and 35 days for the active-member markers; the support-ticket TTL is 30 days after closing, the anniversary daily marker is 7 days after it was claimed, and the deal catalogue and the announcement records are purged at 90 days — the catalogue from the moment the promotion ends, the announcement records from the moment of posting — while deal notifications do not expire on their own. The activation record for optional modules is kept while the server exists and is deleted with that server's data purge, with no expiry of its own; the purchase order for a paid plan is kept after that purge, as a billing record, and it contains no member data. When a user requests erasure, the bot also deletes the Discord messages it posted on their behalf (their suggestion cards, their starboard highlights and their temporary voice channels), not only the database rows.

6. Your rights (Argentine Law 25.326)

Under Law 25.326:

  • Art. 14 — right of access, rectification, update, and suppression of data (habeas data).
  • Art. 16 — handling of minors' data requires legal-representative involvement under Argentine law.
  • Right to file with the Agencia de Acceso a la Información Pública (AAIP).

How to exercise them

Email neceldev@gmail.com including your Discord user ID (enable Developer Mode → right-click yourself → Copy ID) and, for server-scoped data, the guild name. The operator may ask to reasonably confirm the request comes from the account owner. Target response time: within 30 days.

Users outside Argentina: these rights may be exercised by all users, regardless of their country or jurisdiction of residence. If you are in a jurisdiction with equivalent data-protection frameworks (for example, the GDPR in the European Union, the CCPA/CPRA in California, or similar regulations), you may request access, rectification, deletion, portability, and objection to the processing of your data by emailing the same address: neceldev@gmail.com.

Self-service commands exist for:

  • Birthdays: /birthday delete
  • Reminders: /remind cancel
  • AFK status: cleared automatically by your next message, or with /data delete
  • Trivia stats: /data delete
  • XP, seasons, and /wrapped: /data delete
  • Daily Wordle results: /data delete
  • Suggestions: /suggest delete (author or staff) or /data delete
  • Starboard highlights: removed when the original message is deleted, or with /data delete
  • Temporary voice channels: closed when the channel is emptied, with /tempvoice delete, or with /data delete
  • Giveaways: auto-purged 7 days after closing, or with /data delete
  • Tasks: per-task delete
  • Deal notifications: the server removes them from /deals; /data delete erases the ID of the administrator who created them
  • Server admins: can remove their server's warnings (/warns remove), knowledge entries, and config.

Users can exercise their right of access and deletion directly via the /data command in any server where Hiraeth is present. /data export provides a machine-readable copy of all stored personal data; /data delete permanently removes it.

Moderation records tied to server administration remain the server admins' responsibility; users should contact server staff for those (the developer does not adjudicate moderation).
